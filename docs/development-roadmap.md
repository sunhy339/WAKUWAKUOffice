# WAKUWAKUOffice 开发路线与验收跟踪

## 1. 基本信息

- 当前开发分支：`feature/auth-recovery`
- 集成开发分支：`develop`
- 稳定基线分支：`main`
- `develop` 当前基线提交：`50ad355abf9f77259fd68ec07d143cbaeaa0c6c4`
- 开发规范：[universal-software-development-standard.md](./universal-software-development-standard.md)
- 当前原则：保留现有功能，采用小步迭代；每个功能完成后先进入“待验收”，经用户确认后才标记为“已完成”。

### Git 分支约定

1. `main` 只保留稳定基线和正式发布版本，不直接进行功能开发。
2. 新功能从 `develop` 创建 `feature/<功能名>` 分支；修复也必须在独立功能分支完成。
3. 功能分支完成自测、部署验证并交给用户验收后，才允许合并到 `develop`。
4. 用户未明确验收通过时，功能分支保持独立，不能通过“看起来可用”推断已完成。
5. 合并前必须确认工作区干净、变更范围明确，并保留可回滚的提交记录。

## 13. P1-05 实现记录：在线对象存储适配（待验收）

### 当前实现

- 增加统一存储适配层，`local` 保持现有本地磁盘行为，`s3` 兼容 MinIO、Amazon S3、R2 等 S3 API 服务。
- 文件上传、聊天生成文件、下载、流式播放、预览、缩略图和删除统一经过适配层；现有 `/api/files` 接口不变。
- `files` 表增加 `storage_backend` 和 `storage_key`，旧记录默认使用 `local`，继续通过 `file_path` 读取。
- 对象键使用 `users/<owner_id>/files/<uuid>.<ext>`，避免不同用户之间发生路径混用；S3 访问密钥只从服务端环境变量读取。
- 配置不完整时服务启动即失败，避免线上运行后才发现上传链路不可用；本地默认配置不需要 MinIO。
- 增加 `--migrate-storage` 一次性迁移命令：复制旧本地文件到 S3 并更新数据库，默认保留本地副本，避免迁移失败造成数据丢失。
- 远程服务器已部署独立的 MinIO 容器、私有 bucket 和 WaKuOffice 应用容器；本次已完成真实的注册/JWT、MinIO 上传/下载/删除和健康检查验收，用户确认前仍保持“待验收”。

### 待验收

1. 使用 `STORAGE_BACKEND=local` 启动，确认旧文件和新上传仍能读取。
2. 部署 MinIO 并创建私有桶，填写 `STORAGE_S3_*` 参数后，验证上传、预览、下载和删除。
3. 使用 `--migrate-storage` 验证旧本地文件复制到对象存储后仍可读取，确认本地副本保留。
4. 验证对象存储暂时不可用时，页面能看到失败而不是产生错误的文件记录。
5. 确认用户不能通过文件接口读取其他用户的对象键。

| 维度 | 约束 |

| 数据边界 | 后端事实状态、Zustand 页面状态、组件临时状态分开维护 |
